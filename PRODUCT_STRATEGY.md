# Satoshi Hunt — Product Strategy

## Positioning
Satoshi Hunt should be a coordination and trust layer for explicitly public computational reward challenges, not merely a single Bitcoin puzzle pool.

## Lessons adopted

### Search4BTC
Adopt:
- low-friction participation
- browser/local contribution model
- batch-based work allocation
- visible contribution dashboard

Improve:
- challenge provenance and verification should be first-class
- avoid tying the platform economy to a separate utility token
- make reward settlement status explicit

### BTC Puzzle
Adopt:
- shared coverage
- duplicate-work prevention
- contribution history
- community features

Improve:
- no hidden/unclear entry economics
- show challenge rules and reward state before work begins
- separate worker contribution from who ultimately receives a reward

### Collision Protocol
Adopt:
- live worker statistics
- transparent contribution metrics
- open/auditable client philosophy
- clear fee disclosure

Improve:
- broader challenge registry
- simpler onboarding for non-GPU users
- stronger account, audit and settlement UX

### OpenPuzzle
Adopt:
- anonymous/local computation boundary
- public range ledger concept
- non-sensitive progress reporting
- independent verification before declaring success

Improve:
- optional account layer for attribution
- clearer reward accounting
- richer worker reliability and contribution history

### BOINC
Adopt:
- volunteer computing principles
- contribution/credit accounting
- redundant verification concepts for unreliable clients

Improve:
- modern consumer UX
- simpler onboarding
- direct challenge/reward transparency

## Product pillars
1. Verified challenge registry
2. Global duplicate protection
3. Local-first computation
4. Proof-based contribution accounting
5. Transparent reward ledger
6. Worker reliability and reputation
7. Public audit trail
8. Clear safety and scope boundaries
9. Mobile-friendly monitoring dashboard
10. Extensible challenge adapters

## Planned UX
- Discover: browse eligible challenges
- Challenge detail: provenance, rules, funding, verification, coverage
- Work: claim, progress, heartbeat, completion
- Account: workers, contribution, verified hours, reward events
- Network: active workers, coverage, reliability and throughput
- Audit: immutable-style event history and settlement state

## Economy
The existing 85/15 worker/platform model remains a product option, but reward settlement must remain reviewable and authorized. Owner/community allocation remains a separate manual process.

## Non-goals
- ordinary wallet/private-key cracking
- covert/background computing
- storing private keys or seed phrases
- automatic Bitcoin transfers
- presenting demo records as live funded challenges

## Competitive goal
Satoshi Hunt should combine the strongest coordination ideas from puzzle pools with the transparency, safety and contribution accounting expected from a modern distributed-computing platform.
